## 一、项目概述

本章说明项目定位、所解决的核心问题、产品与商业模式概览，以及三年发展目标。

### 1.1 一句话定位

「桩」点北邮是一套面向高校与公共机构的**充电车位智能监管系统**。系统以摄像头识别车辆与车牌，将识别结果与充电桩状态融合，自动判定"燃油车占位""异常占位""充满未移车"三类违规；命中违规即短信提醒车主，并结构化落库，供管理方在后台查询、统计与考核。

### 1.2 我们解决的真实问题

新能源汽车在校园与公共机构快速普及，但充电车位长期面临两类"看不见的浪费"：

- **燃油车占用充电车位**——蓝牌车辆停在充电位上，新能源车到了却充不上；
- **新能源车"充满未移车"**——电早已充满，车却长时间不动，把公共资源当成私人车位。

这两类问题长期依靠人工巡查处理，效率低、发现不及时、难以留痕。更关键的是，**"充满未移车"无法用单一手段识别**：只看图像无法判断车是否在充电，只看充电桩数据无法判断车位被谁占用。这正是现有方案普遍失效的地方，也是本项目的立足点。

### 1.3 产品与商业模式概览

| 维度 | 内容 |
|---|---|
| 产品形态 | 软件为主、硬件可选：部署在客户已有摄像头与服务器上；无算力时加配边缘计算盒 |
| 核心能力 | 车辆检测、车牌识别（号码 + 底色判型）、充电状态融合、四规则判定、短信提醒、六页管理后台 |
| 客户对象 | 高校后勤与校园充电设施管理部门、党政机关与公立医院等公共机构后勤部门、园区写字楼运营方 |
| 收入模式 | 一次性平台部署费 + 按监管车位计费的年度授权费 + 短信通道费 + 可选增值模块 |
| 交付方式 | 远程部署为主、现场适配为辅；先做示范场站形成可复制模板，再按场站复制推广 |
| 技术栈 | FastAPI（Python）+ Vue 3 + MySQL 8 + YOLOv8 + HyperLPR，充电状态模拟并预留 OCPP 适配层 |

### 1.4 三条核心竞争优势

1. **唯一能识别"充满未移车"的技术路径**。判定"充满未移车"必须同时知道"车是谁的车"和"桩在不在充电"。只有视觉识别与设备状态融合才能拿到这两个条件，单一技术路线都无法覆盖这一状态。
2. **政策窗口明确、需求刚性**。国家标准 JS/T 302—2026 自 2026 年 3 月 1 日起实施，强制公共机构停车场充电车位配建比例不低于总车位 25%，并鼓励面向社会共享开放。车位数量会成规模增长，"怎么管"随即成为必须回答的问题。
3. **交付成本低、可复制性强**。系统优先复用客户既有的摄像头与服务器，走软件部署而非硬件改造，单场站交付的边际成本低；复制到新校区时主要工作是场景适配，不需要重做硬件工程。

## 二、市场与需求分析

本章从政策、设施存量、用户痛点与客户画像四个角度，说明需求从何而来、规模有多大。

### 2.1 政策驱动：公共机构充电设施进入强制配建期

**JS/T 302—2026《公共机构电动汽车充电基础设施配置及运行指南》**是本项目最直接的政策锚点。该机关事务行业标准由国家机关事务管理局于 2026 年 1 月 19 日发布，**自 2026 年 3 月 1 日起实施**，覆盖各级党政机关、事业单位、团体组织等公共机构，包括公办高校、公立医院与公共文化体育场馆。

标准的关键要求：

| 要求项 | 具体内容 |
|---|---|
| 配建比例 | 充电车位不低于总车位的 **25%** |
| 快慢充配比 | 直流桩 20%–40%（单枪 40–250 kW）；交流桩 60%–80%（单枪不低于 7 kW） |
| 设备准入 | 须取得 CCC 认证 |
| 建设模式 | 可采用自主投资、企业投资、BOT 等模式 |
| 运行管理 | 独立计量、规范收费，接入国家或省级监管平台，鼓励面向社会共享开放 |
| 安全管理 | 充电过程实时监控，监控视频存储不少于 30 天，定期巡检与应急演练 |

这条政策同时改变了三件事：

1. **充电车位的绝对数量会显著增长**——按 25% 的比例要求，一所拥有 1500 个停车位的高校，其充电车位规模将达到 375 个量级，管理复杂度远超人工巡查的承载能力。
2. **管理责任被明确到具体机构**——标准要求"独立计量、规范收费""接入监管平台""实时监控""定期巡检"，意味着管理方必须留下可核查的记录，而不只是"安排了人去看"。
3. **对外开放放大了矛盾**——标准鼓励公共机构充电设施向社会共享开放。一旦社会车辆进入，占用纠纷从"内部协调"变成"对外服务"，缺少结构化记录会让管理方在争议中处于不利位置。

除本条标准外，《新型电力系统建设"十五五"规划》提出到 2030 年全国充电基础设施总量超过 4000 万个、形成支撑超过 1.1 亿辆电动汽车的充电服务能力。政策方向在中期内不会逆转。

### 2.2 市场基础：存量设施与增量设施同时扩大

| 指标 | 数值 | 说明 |
|---|---|---|
| 全国机动车保有量 | 4.76 亿辆（汽车 3.71 亿辆） | 截至 2026 年 6 月底，公安部交通管理局 |
| 新能源汽车保有量 | 4897 万辆，占汽车总量 13.19% | 同比提高 2.92 个百分点 |
| 纯电动汽车保有量 | 3367.5 万辆，占新能源汽车 68.77% | 纯电是充电车位的直接需求方 |
| 2026 上半年新注册新能源汽车 | 519.5 万辆，占新注册汽车 49.42% | 新增车辆中近半为新能源，需求端增速高于存量 |
| 全国充电基础设施（枪） | 2305.7 万个，同比 +43.2% | 国家能源局，截至 2026 年 6 月底 |
| 其中公共充电设施（枪） | 500.9 万个，同比 +22.3% | 本项目的主要监管对象 |
| 其中私人充电设施（枪） | 1804.8 万个，占全部约 78% | 说明公共桩服务压力更集中 |
| 县域充电设施覆盖率 | 98.61% | 设施覆盖已基本完成，问题转向"用得好不好" |

一个关键判断：**充电设施的数量增长已经领先于管理能力的增长**。公共充电设施 500.9 万个、同比增长 22.3%，同期针对"车位被占用"的调查却显示近半数新能源车主把占位列为最突出的痛点。设施在变多，可用率却没有同步提高——这正是本项目切入的位置。

### 2.3 需求痛点：车位被占是各方公认的第一痛点

三份独立调查指向同一个结论：

| 调查来源 | 样本与方法 | 关键结论 |
|---|---|---|
| 中国消费者协会《住宅小区物业服务调查报告》（2026 年 7 月） | 全国住宅小区物业服务调查 | 反映"充电位置经常被燃油车占用"的车主占 **35.60%**，与"充电桩数量不够"（36.92%）几乎并列第一，两项合计超过七成 |
| 绿领环保《2026 天津中心城区新能源汽车公共充电设施友好度观察报告》（606 份问卷） | 公众意见分析 | **45.24%** 的新能源车主将"燃油车占位"列为充电设施最突出的痛点，居各项痛点之首 |
| 杭州市消保委电动汽车充电服务问卷调查（2026 年 2 月，据媒体报道） | 用户问卷 | 充电车位被非电动车占用"经常遇到"50.17%、"偶尔遇到"38.01%，合计 **88.18%**（该数据未取得官方原文，仅作旁证） |

绿领环保的调查还揭示了一个对本项目定价与产品设计有直接价值的细节：车主对"占位收费"并非一味反对——**45% 有条件支持**（前提是设置免费缓冲期、标准透明、有挪车提醒），完全支持 15%，明确反对 25%。这说明市场的阻力不在于"要不要管"，而在于**管理手段是否公平、可解释、有提醒**。而这恰好是"先提醒、后处理"的产品逻辑：本项目默认动作是短信提醒车主移车，而不是直接处罚。

### 2.4 目标市场测算

测算方法：自下而上，以**纳入监管的充电车位数量**为计量单位，乘单位车位年费。所有假设均在文中列出，读者可自行替换参数复算。

**总体市场（TAM）**：以全国公共充电设施 500.9 万个为基数，近似按 1 桩对应 1 个充电车位计，全国公共充电车位约 500 万个。按单位监管服务费 200 元/车位·年测算，**年度市场规模约 10 亿元**。若计入一次性平台部署费，单场站全周期价值更高，此处取年费口径作为保守下限。

**可服务市场（SAM）**：政策强制配建、管理主体明确、采购决策链清晰的公共机构场景。

| 客户群 | 规模基数 | 车位测算假设 | 可服务车位数 |
|---|---|---|---|
| 高校 | 全国高等学校 3196 所（教育部，截至 2026-06-17） | 按 JS/T 302 配建比例与中等校园停车场规模估算，取首期可监督 200 个充电车位/校 | 约 64 万个 |
| 党政机关、公立医院、公共文体场馆 | 按高校场景规模的 2–3 倍估算 | — | 约 128–192 万个 |

合计 SAM 约 **190–260 万个充电车位**，对应年度服务费市场约 **3.8–5.2 亿元**。测算中的"首期可监督 200 个车位/校"是保守取值：政策要求按总车位 25% 配建，而项目首期只需覆盖其中管理矛盾最集中的核心区域。

**可获取市场（SOM，三年）**：以北京地区高校及周边公共机构为起步半径，三年累计签约约 41 个场站，对应约 3280 个监管车位；三年累计合同额约 220 万元，第 3 年稳态年化收入约 140.6 万元。占 SAM 的比例约 0.1%，目标设定留有充分余量。

> 说明：SOM 的单位经济与逐年分解见第八章。SOM 之所以取"场站"而非"车位"为推进单位，是因为采购与决策发生在场站（学校 / 机构）层面。

## 三、产品与服务

本章说明产品定位、业务闭环、功能模块、技术方案、技术壁垒与合规安排。

### 3.1 产品定位

本项目交付的**不是硬件，而是"识别 + 判断 + 提醒 + 留痕"的管理能力**。产品优先部署在客户已有的摄像头与服务器上；只有当现场没有可用算力时，才配置边缘计算盒。这一定位决定了三件事：交付成本低、部署周期短、客户的决策阻力小。

### 3.2 核心业务闭环

```
抽帧 → 车辆检测 → 车牌识别（号码 + 类型）
     → 查库关联（车辆 / 充电桩绑定）→ 获取充电状态
     → 违规判断（规则引擎）→ 命中则短信提醒 + 落库
     → 后台可视化展示
```

四条判定规则：

1. 燃油车（蓝牌）占用充电位 → **违规占位**
2. 新能源车未充电且久停 → **异常占位**
3. 新能源车充满超时未驶离 → **充满未移车**
4. 正常充电 → **不提醒**

车型判定的口径需要特别说明：系统以**车牌底色**判定车型（绿牌 = 新能源，蓝牌 = 燃油），而不依赖车辆外观分类。原因是车牌类型是可靠且法定的代理变量，外观分类在校园场景下受车型数量、拍摄角度与光照影响过大，准确率不可控。这一取舍已写入接口契约，避免后续各部门各自解释。

### 3.3 功能模块与交付内容

| 模块 | 内容 | 交付形态 |
|---|---|---|
| M1 图像采集 | 读视频 / 图片，定时抽帧 | 后端服务 |
| M2 车辆检测 | 检测车辆，输出边框与置信度 | 算法模块 |
| M3 车牌识别 | 定位车牌、识别号码、判定类型 | 算法模块 |
| M4 充电状态 | 车牌与桩状态关联、定时更新、预留 OCPP 适配层 | 数据服务 |
| M5 违规判断 | 四规则判定，阈值可配置 | 规则引擎 |
| M6 短信提醒 | 查车主手机号、发送、记录状态 | 通知服务 |
| M7 管理后台 | 车辆信息管理 / 违规记录查询 / 充电状态展示 / 报警统计 / 系统参数配置 / 实时识别预览（六页） | Web 应用 |

六页后台即管理方日常使用的完整界面。其中"系统参数配置"页让阈值（如充满后允许停留时长、异常停放判定时长）由管理方自行调整而无需改动代码——阈值一律从配置表读取，不硬编码，这是交付后可运维的前提。

### 3.4 技术方案

五层架构与关键选型：

| 层级 | 职责 | 关键实现 |
|---|---|---|
| 图像采集层 | 摄像头 / 测试视频 → 定时抽帧 | OpenCV 抽帧，输出标准化帧 |
| 智能识别层 | 车辆检测 + 车牌识别 | Ultralytics YOLOv8 + HyperLPR（主）/ PaddleOCR（备选） |
| 数据融合层 | 按车牌号关联车辆与充电桩状态 | MySQL 状态库 + 模拟器 |
| 业务处理层 | 违规判断规则引擎 | Python 规则函数，阈值可配置 |
| 应用展示层 | 后台管理 Web + 提醒通道 | Vue 3 + FastAPI + 短信网关 |

| 选型项 | 方案 | 选择理由 |
|---|---|---|
| 后端 | FastAPI（Python 3.11.x） | 异步框架，接口契约可自动生成 OpenAPI 文档 |
| 前端 | Vue 3 + Vite + TypeScript + Element Plus | 组件成熟、交付快，适合以表格与图表为主的后台 |
| 数据库 | MySQL 8（开发期以 SQLite 等价验证） | 数据访问层走 SQLAlchemy，切换数据库只改连接串 |
| 目标检测 | Ultralytics YOLOv8（n / s） | 预训练起步，配合校园场景微调 |
| 车牌识别 | HyperLPR（主）/ PaddleOCR（备选） | 同时给出号码与底色判型 |
| 可视化 | ECharts | 统计图表配色统一从设计令牌读取，保证多页一致 |

数据模型为核心四表：车辆表（车牌、车型、车主、手机号）、充电桩表（桩号、状态、绑定车牌、起止时间）、违规记录表（记录号、车牌、车型、桩号、命中规则、发生时间、提醒状态与时间）、系统配置表（阈值键值）。

### 3.5 技术壁垒与工程方法

**壁垒一：融合判断的方法论沉淀。** 本项目的技术要点不在单个模型的精度，而在"视觉识别 + 设备状态"的融合判断路径——只有在两个信号同时可用时，才能区分"合法占用"与"违规占用"，并识别出"充满未移车"这一既非占位违规、又确实浪费资源的中间状态。这条路径不止适用于充电车位，凡需要区分"合法占用"与"违规占用"的场景（专用车位、无障碍车位、装卸货位）均可迁移。

**壁垒二：校园场景数据与适配经验。** 公共数据集难以覆盖校园特有的拍摄角度、光照变化、车位划线样式与车型分布。项目在实施过程中同步积累校园场景标注数据（已按规则类别组织样本与标注），每交付一个新场站就多积累一份场景适配经验，形成滚动的数据资产。

**壁垒三：可复制的工程方法。** 项目采用两条工程策略控制交付风险：

1. **契约先行**——数据模型、接口签名与返回结构先固化进接口契约文档，三人并行开发不靠口头约定、不互相猜测。这既是团队协作方式，也是交付给客户的技术资产（接口可自动生成文档）。
2. **桩替身解耦**——最慢、最不确定的环节先用替身顶上：识别环节先用"识别桩"（读标注文件）、提醒环节先用"沙箱"（写库 + 日志）。**先用替身证明闭环能跑通，再逐段替换为真实模型与真实短信**，且真实实现与替身返回同一数据结构，替换时上层零改动。这套方法让"最慢的一环"不再阻塞整体交付。

### 3.6 知识产权与合规安排

- **软件著作权**：项目结题阶段提交计算机软件著作权登记申请，条件允许时申请实用新型专利。
- **开源许可（关键合规项）**：当前使用的 Ultralytics YOLO 系列默认采用 **AGPL-3.0** 许可。AGPL-3.0 的网络服务条款要求：若以网络服务方式向用户提供服务，须向用户开放整个应用的源代码。因此：

| 阶段 | 合规安排 |
|---|---|
| 校内研发与竞赛阶段 | 属非商业原型，AGPL-3.0 允许自由使用 |
| 对外商业交付前 | 必须二选一：① 向 Ultralytics 取得 **Enterprise License**（官方需询价，第三方资料给出的量级参考为 10K 美元/年级别，需以实际报价为准）；② 将检测模型切换至 Apache-2.0 许可的替代方案（如 RT-DETR、RF-DETR 等），并逐个核对权重与依赖的许可 |

  该事项已作为独立风险项（R3）列入第九章，并设定明确决策点，不留给交付期解决。

## 四、商业模式

本章说明客户与价值主张、收入结构、定价依据、成本结构与单位经济模型。

### 4.1 模式总览

| 要素 | 内容 |
|---|---|
| 客户 | 高校、党政机关与公共机构后勤管理部门（B 端 / G 端，非 C 端） |

### 4.2 收入结构

| 收入项 | 性质 | 说明 |
|---|---|---|
| 平台部署费 | 一次性 | 含软件部署、参数配置、场景适配、人员培训 |
| 点位年度授权费 | 经常性（核心） | 按纳入监管的充电车位数量计费，含算法迭代与后台托管 |
| 短信通道费 | 用量计费 | 代发提醒短信，按条计费 |
| 增值模块费 | 可选、一次性 | 占位费结算对接、监管平台数据上报、定制报表等 |

收入的健康度取决于第三项的经常性占比：随着存量场站累积，点位年费从第 1 年的 0 提升至第 3 年的约 25.6 万元，加上当年新增点位年费共 65.6 万元，占第 3 年收入的 46.7%，**经常性收入占比接近一半**。这是本项目从"项目制交付"走向"可续约服务"的关键指标。

### 4.3 定价策略与依据

| 收费项 | 假设定价 | 定价理由 |
|---|---|---|
| 平台部署费 | 30,000 元 / 场站 | 相当于 4–6 人日的实施工程量；因为复用客户既有摄像头与服务器，显著低于需要硬件改造的同类方案 |
| 点位年度授权费 | 200 元 / 车位·年 | 折算每月不足 17 元/车位，低于一名巡查人员月度人力成本的零头；对一个 80 车位场站即 1.6 万元/年，落在高校与公共机构的常规信息化预算科目内 |
| 短信通道费 | 0.08 元 / 条 | 采购成本约 0.045–0.05 元/条，含通道与运维加价 |
| 增值模块 | 10,000 元 / 场站 | 覆盖定制开发工作量 |

**定价原则**：让客户的年度支出低于其现有巡查成本，使采纳决策不依赖"新增预算"而依赖"替换原有支出"。这一定价策略在公共机构客户中尤其重要——它们的预算是年度既有科目，新增预算的审批链条远长于科目内部调整。

> 提示：以上价格均为**基于工程量与替代成本的假设值**，尚未经过客户验证。价格验证已列入第 9.2 节的关键假设清单。

### 4.4 成本结构

| 成本类别 | 构成 | 性质 |
|---|---|---|
| 交付与变动成本 | 部署实施人工（约 4 人日）、场景适配与模型调参（约 2 人日）、云资源、短信通道、差旅 | 随场站数变动 |
| 人力费用 | 全职实施工程师、兼职实施人员 | 阶梯式固定 |
| 软件许可与合规 | 检测模型商业授权（或替代方案迁移成本） | 固定 |
| 云基础设施与市场推广 | 训练与演示环境、宣传材料、行业会议与走访 | 固定 |

成本结构的两个特征值得强调：其一，**边际成本低**——因为复用客户硬件，每新增一个场站的增量成本主要在人力而非物料；其二，**续费的成本极低**——存量场站第 2 年起几乎只产生云资源与短信成本，因此续费业务的毛利显著高于新签业务。

### 4.5 单位经济模型（单个 80 车位场站）

| 项目 | 金额 | 备注 |
|---|---|---|
| 首年合同额 | 46,000 元 | 部署费 30,000 + 点位年费 80 × 200 = 16,000 |
| 首年交付成本 | 13,700 元 | 实施 6,000 + 场景适配 4,000 + 云 1,200 + 短信 500 + 差旅 2,000 |
| 首年毛利 | 32,300 元 | 毛利率约 70% |
| 第 2 年起年收入 | 16,000 元 | 仅点位年费 |
| 第 2 年起年成本 | 1,700 元 | 云 1,200 + 短信 500 |
| 续费年毛利 | 14,300 元 | 毛利率约 89% |

以一个三年合作周期计（首年 + 两年续费），单一客户的价值约 7.8 万元，对应毛利约 6.1 万元；若合作延续到第五年，价值可到 11 万元。这解释了为什么"续约率"是本项目最重要的经营指标。

## 五、竞争分析

本章梳理现有方案的格局与各自短板，说明本项目的差异化位置与壁垒强度。

### 5.1 现有方案格局

市场上处理"充电车位被占用"问题的方案分三类，各有明确短板：

| 方案类型 | 已有能力 | 关键短板 |
|---|---|---|
| 充电运营类应用 | 设备监测、找桩导航、计费结算 | 侧重充电服务本身，基本不介入车位占用监管，无法识别并追责占位车辆 |
| 以车牌识别为核心的智慧停车系统 | 车牌识别、道闸控制、停车计费 | 拿不到充电状态数据，因而无法区分"正在充电"与"充满未移车"，容易误判漏判 |
| 人工巡查 + 视频监控 | 可处理明显占位，可人工干预 | 成本高、时效差、缺少结构化记录，难以支撑统计与考核 |

需要说明的是，充电运营领域的头部平台（如特来电、星星充电、云快充等）在设备规模与用户覆盖上远非本项目可比，其优势集中在充电交易与网络运营。本项目的判断是：**充电车位占用监管不是充电运营平台的主战场**，其业务重心在电量与交易，而不是车位秩序。这一判断是竞品分析的起点，也是本项目选择"做监管层、不做交易层"的原因——与运营平台是互补关系而非替代关系。

### 5.2 差异化定位

本项目的差异点可以压缩成一句：**判定违规所必需的"充电状态"这一维度，只有与视觉识别联合才可获得。**

由此形成的三项具体差异：

1. **能识别"充满未移车"**。这是三类现有方案共同的盲区：运营平台知道桩在充电但不知道车位被谁占；智慧停车知道车牌但不知道桩的状态；人工巡查则既贵又慢。而这一状态恰恰是车主投诉最集中的场景之一。
2. **以提醒为主、处罚为辅**。车主调查显示，45% 的人对占位收费"有条件支持"，前提是免费缓冲期、标准透明、有挪车提醒。产品默认先发提醒短信，把"及时通知"作为核心动作，这既降低了推行阻力，也让管理方在争议中占住"已尽提醒义务"的位置。
3. **为监管留痕，而非只为计费**。监管平台的数据上报、日常巡检记录、安全监控留痕，都是 JS/T 302—2026 明确提出的运行管理要求。本项目按"可核查记录"设计数据模型，而不是按"收停车费"设计。

### 5.3 竞争壁垒与可持续性

| 壁垒 | 说明 | 可持续性 |
|---|---|---|
| 方法论 | 融合判断的规则体系与参数设计 | 中——方法可被学习，但先发者已积累场景参数 |
| 数据资产 | 校园场景标注数据集与场景适配经验库 | 高——随交付场站数增长而累积，后来者难以短期复制 |
| 客户关系与合规记录 | 公共机构采购看重已交付案例与运行记录 | 高——公共机构客户一旦上线，切换成本高 |
| 与运营商的关系 | 定位为监管层，可与充电运营商形成数据互补 | 中高——关系建立需要时间，但一旦建立粘性强 |

需要诚实指出：本项目的技术门槛属于**工程实现与场景经验的复合门槛，而非算法原始创新的门槛**。真正的护城河来自"先进入 + 场景数据 + 客户合规记录"的组合，而不是某个模型本身。这也意味着竞争策略应当以**尽快复制场站数量**为核心。

## 六、营销与推广策略

本章说明推广路径、推广手段与渠道合作方式，以及推广节奏上的取舍。

### 6.1 三阶段推广路径

| 阶段 | 目标客户 | 目标 | 主要依据 |
|---|---|---|---|
| 第一阶段：校内示范 | 北京邮电大学 | 建成可对外演示与参观的示范场站 | 团队自身就在校内，可获得真实场景与真实用户反馈；示范场站是最有效的销售资料 |
| 第二阶段：同类高校复制 | 北京地区高校 | 签约首批外部高校客户 | 高校之间存在密集的后勤交流渠道；同类场景的适配经验可直接复用 |
| 第三阶段：公共机构与园区 | 党政机关、公立医院、公共文体场馆、园区写字楼 | 扩大客户类型，验证跨场景通用性 | JS/T 302—2026 对公共机构明确要求运行管理与开放共享，需求刚性 |

**关于推广节奏的取舍**：公共机构客户的采购周期长、决策链复杂，短期内难以形成规模收入。因此策略上先用高校场景完成产品打磨与案例积累（高校决策链相对短、场景同质化高），再以成熟案例切入公共机构。这样安排可以避免团队在早期被长周期采购拖住。

### 6.2 推广手段

1. **示范场站参观**。对公共机构客户而言，最有效的说服方式不是方案 PPT，而是到现场看一次"燃油车停在充电位 → 短信发出 → 后台出现记录"的完整过程。
2. **竞赛与展示平台**。以创新创业竞赛、科技展会与校园科技活动作为对外展示窗口，其价值不只是获奖，更在于获得行业评委与主管部门的背书与联系方式。
3. **学术与行业渠道**。依托学院与指导教师的行业关系，触达高校后勤管理与机关事务管理部门的专业交流场合。
4. **内容与数据公开**。定期发布校园充电车位占用情况的分析报告（脱敏口径），以数据引发关注并建立专业形象。这类内容成本低，但对"要不要管、管到什么程度"的讨论有直接推动作用。

### 6.3 渠道与合作

| 合作方 | 合作方式 | 对本项目的价值 |
|---|---|---|
| 充电桩运营商 | 补能状态数据接口对接、OCPP 适配协作 | 解决"充电状态"数据获取的长期来源，替代当前的模拟数据 |
| 高校后勤管理部门 | 示范场站共建、使用反馈 | 获取真实场景数据与首批客户背书 |
| 属地机关事务管理部门 | 参与标准落地试点 | 进入公共机构客户名单的合规路径 |
| 系统集成商 | 作为分包模块嵌入其智慧校园 / 智慧园区方案 | 借渠道快速扩大场站覆盖 |

系统集成商渠道值得单独说明：智慧校园与智慧园区的总包方通常需要"充电车位监管"这类细分功能模块，但自行研发不经济。本项目以模块形式嵌入其方案，可以在不承担客户获取成本的前提下快速扩大部署场站数，同时把实施工作量留在对方一侧。这对一个以人力为主要成本的团队而言是更高效的增长路径。

1. **能力互补且无重叠**。一人负责集成与前端、一人负责数据与算法、一人负责视觉设计，三条线并行且彼此依赖清晰，减少了常见的"三个算法工程师做一个前端"的结构性浪费。
2. **同学院、同作息、可高频协同**。三人同院，能保证周会与结对调试的稳定性，这对需要跨模块联调的系统项目至关重要。
3. **已有可验证的工程纪律**。团队在项目初期即建立了接口契约文档、分支策略与"改动必提交、交付必测试"的规范，并已通过端到端闭环与自动化测试验证——交付给客户的代码质量不是承诺，而是可查看的既成事实。
4. **有指导教师的技术路线把关**。阶段性评审机制避免了团队在错误的技术方向上投入过多时间。

**协作机制**：

- **分支策略**：主干为保护分支，功能开发使用独立分支，由负责人统一合入，避免多人合并弄乱主干。
- **提交规范**：每完成一步即提交，提交信息按"模块：简述"格式书写，保证可追溯、可回滚。
- **契约变更流程**：任何接口调整须先修改契约文档、全员通告并升版本号，之后才能改动代码，禁止单方面改动己方接口。
- **周会节奏**：每周固定同步"已完成 / 卡点 / 下周需要对方提供什么"，由负责人完成合入。

### 7.4 团队短板与补强计划

需要坦率承认：团队三人均为通信与信息技术方向在读学生，**缺少商业化与市场运营经验**，也缺少面向客户的商务谈判经验。补强方式为：

1. 依托学校创新创业学院与竞赛配套的创业辅导资源，补齐商业知识；
2. 引入校内有商务实践经验的成员或顾问参与客户沟通；
3. 早期推广以"技术演示 + 试用"为主，把商务环节的复杂度降到最低。

2. **首批 3 个场站交付后**——复核单场站实际交付成本与部署人日。若显著高于假设，需要重新定价或改变交付方式（例如转为远程部署 + 客户自助实施）。
3. **第 2 年末**——评估外部客户收入占比。若低于预期，需要重新审视渠道策略，优先投入系统集成商渠道。

## 十、预期成果与社会效益

本章说明项目交付的成果形式、社会效益与长期发展愿景。

### 10.1 成果形式

- 一套可完整演示的校园充电桩车位防占智能管理系统（后端服务 + 六页管理后台 + 算法模块）；
- 车辆检测、车牌识别、充电状态融合、违规判断、短信提醒等核心功能模块；
- 项目技术报告、用户使用说明书、结题报告；
- 计算机软件著作权（条件允许时申请实用新型专利）；
- 创新创业竞赛参赛材料及本商业计划书。

### 10.2 社会效益

| 维度 | 效益 |
|---|---|
| 绿色低碳 | 提高单位充电设施的服务车次，让已建成的充电桩真正被用上，减少"设施闲置 + 用户排队"并存的结构性浪费 |
| 公共资源公平 | 公共机构充电设施按政策要求向社会开放后，占用监管是"开放"能够持续的前提；缺少秩序，开放就难以落地 |
| 校园治理数字化 | 把车位管理从"人管"推向"数管"，形成可统计、可考核、可追溯的记录，为车位规划与充电桩扩容提供数据依据 |
| 管理成本 | 违规发现由人工巡查转为自动识别与主动提醒，直接降低巡查人力投入 |
| 育人价值 | 团队成员在真实需求下完成从需求分析、契约设计、算法实现到交付验收的完整工程训练，成员的技术能力与工程规范意识得到系统锻炼 |

### 10.3 发展愿景

**短期**：把校园充电车位的管理从"人管"推向"数管"，以"识别—判断—提醒"的自动闭环提升车位周转率、降低巡查成本。

**中期**：形成一套低成本、可复制、可裁剪的智慧场站方案，从校园走向党政机关、医院、文体场馆与商业园区，成为公共机构落实充电设施运行管理要求时的可选工具。

**长期**：沉淀"视觉识别 + 设备状态"融合判断的方法论。这套方法的价值不限于充电车位——凡需要区分"合法占用"与"违规占用"的场景（专用车位、无障碍车位、装卸货位、消防通道）都存在同类问题。长期目标是把这套判断能力做成可复用的基础模块，而本项目是其第一个落地场景。
