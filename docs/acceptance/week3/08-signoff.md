## 三、签字前请重点核对这 7 条（最容易签错的地方）

1. **判重键不含 `notify_status`**（S3）：v1.2 的「已提醒过就新增一条」已废止。
   若前端或统计仍按「出现次数 = 提醒次数」理解，签下去就是两套口径。
2. **复用时不刷新 `occur_time`**（S3）：第 2/4 页的时间列是「首次发生时刻」，
   不是「最近一次看到」。签名即确认前端不做「按 `occur_time` 排序看出轮询次数」的设计。
3. **`notify_status` 不再由调用方传入**（S4）：`POST /api/notify` 的入参是「记录 ID + `retry` 意图」，
   状态由沙箱结果产生。前端不能再「点一下就当已提醒」。
4. **`notify_attempts` 进程重启不清零**（S4）：这是 A07 的凭据基础，
   也意味着**同一次占用最多只会尝试 `NOTIFY_MAX_ATTEMPTS` 次**，人工重试受同一上限约束。
5. **`FRAME_SOURCE_DIR` 同时决定编排取帧与 real 识别读图**（S1）：两处如果各写一份，就会出现
   「识别结果挂到另一帧的摘要上」（A10 串帧）。签名即确认**只保留一个来源**。
6. **real 模式的失败一律显式报错**（S1）：图缺失 404 / 缺依赖 503 / 未检出车牌 422 /
   检出框但 OCR 空号码 422。**不接受「空号码静默判成无违规」** —— 那会让失败看起来像成功。
7. **`elapsed_ms` 不参与判定**（S1）：它只用于性能凭据与慢帧定位。
   签名即确认 A05/A07 的结论由 `newly_notified` 与 `notify_attempts` 得出，不看耗时。
