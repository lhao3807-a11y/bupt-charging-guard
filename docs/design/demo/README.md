## 2. 截图方法（可复现）

**关键点：截图必须来自真实运行的前后端，且数据要由系统自己产生**（不能手改数据库或前端 mock）。

### 2.1 启动服务

```bash
# ① 后端（开发期 SQLite，启动时自动建表 + 灌种子）
cd backend
<venv>/python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000

# ② 前端
cd frontend
npm run dev          # http://localhost:5173
```

> ⚠️ Vite 在部分 Windows 环境监听的是 **IPv6 `[::1]:5173`**，用 `http://127.0.0.1:5173`
> 会连不上，请用 `http://localhost:5173`。

### 2.2 产生演示数据（走真实判定与提醒接口，已脚本化）

后端种子**不含违规记录**（`occupation_record` 为空），需通过契约端点产生。
脚本直接向 `POST /api/judge` 提交与后端种子绑定一致的识别结果字段（命中即落库），
再调用 `POST /api/notify` 改变提醒状态。它不调用 `/api/recognize`；完整识别链路由独立的端到端检查覆盖。

```bash
python docs/design/tools/demo_seed.py        # → 9 条记录，覆盖规则 ①②③ 与三种提醒状态
```

它**不直连数据库、不改 SQL、不动前端 mock**，只打契约端点。两条口径说明：

- **记录的 `occur_time` 取自 `/api/judge` 入参的 `frame_time`** —— 规则引擎把它当作「判定时刻」
  （`backend/app/rule_engine.py` 顶部口径 2）。因此造出跨越几天的记录**不需要改系统时钟**。
- `frame_time` 与车牌必须落在种子数据上（车牌 → 桩的绑定来自 `backend/sql/schema.sql`），
  脚本里的 `DEMO` 表已与种子对齐：

| 车牌 | 车型 | 绑定桩（种子） | 判定 |
|---|---|---|---|
| `京A88888` | 燃油 | `PILE-004` 空闲 | `rule_hit = 1` 燃油车占位 |
| `京AD24680` | 新能源 | `PILE-003` 空闲 | `rule_hit = 2` 异常占位（久停 > `abnormal_park_min`） |
| `京AD67890` | 新能源 | `PILE-002` 已充满 | `rule_hit = 3` 充满未移车（充满 > `full_timeout_min`） |
| `京AD12345` | 新能源 | `PILE-001` 充电中 | **`null`** —— 规则 ④ 正常充电，不落库（契约明确行为） |

> ⚠️ **幂等性**：引擎只复用「同一桩 + 同一规则 + **仍未提醒**」的记录，
> 所以重复跑本脚本会按「新违规」口径**追加**记录。想要干净的一套数据：
> 停后端 → 删开发库 `backend/app.db`（gitignore 的可再生产物，启动时自动重建 + 灌种子）→ 重启后端 → 跑脚本。

### 2.3 截图 + 美化（一条命令）

第 2 周踩过的坑：`agent-browser` 首次拉 Chromium 卡死 16 分钟，**不靠谱**；
而本机装了 Edge（Chromium 内核），它的无头截图参数与 Chrome 完全一致。于是把
「拍摄 → 套设备框」写成了脚本，颜色从 `tokens.css` **读**而不是抄：

```bash
python docs/design/tools/demo_screenshots.py              # 拍摄 + 美化
python docs/design/tools/demo_screenshots.py --frame-only # 只重做美化（改了框子时用）
python docs/design/tools/demo_screenshots.py --shoot-only # 只重拍（页面改了时用）
```

产物：

| 路径 | 内容 |
|---|---|
| `screenshots/raw/*.png` | **原始截图**（未加工，视口 1600×880），保留它是为了「证明这是真实页面」 |
| `screenshots/*-framed.png` | **美化版**：统一设备框 + 窗口标题条 + 图注，直接进 PPT |

脚本里 `PAGES` 是唯一要维护的地方（7 行：6 页 + 登录页）。拍摄参数：无头 Chromium、
视口 **1600×880**、`--virtual-time-budget=10000`。每次先写独立临时 PNG，浏览器成功退出后
才替换旧原图，避免拍摄失败却误用上次的截图。

> ⚠️ **`--virtual-time-budget` 不能省**：SPA 的懒加载路由组件在截图那一刻可能还没挂载，
> 少了它拍出来是「骨架在、内容区空白」。第 2 周实拍验证过，不是理论风险。
> 取 10000（而非 8000）：第 4 页要多等 ECharts 初始化与主题令牌读取。

> **第 3/4/5 页现走正式路由**：C1–C3 通过 Vite 代理访问隔离演示库；
> 第 3 页显示后端种子桩，第 4 页显示 `demo_seed.py` 经判定与提醒 API 生成的记录，
> 第 5 页显示数据库种子阈值。图注写明「演示数据」，不表示校园实测。

> ⚠️ **`raw/` 是交付物的一部分，不是临时文件。** 任务书对 6.10 的硬要求是「截图须真实页面，
> **不许用线框冒充**」，这句话已落成机械断言（`check_tokens.py` [6] 项）：每张 `*-framed.png`
> 必须在 `raw/` 有同名原件、美化版尺寸必须大于原件、同批原件视口必须一致。
> 也就是说**删掉 `raw/` 会让设计校验直接变红** —— 这是有意的：没有原件就证明不了「这是实拍的」。

### 3.2 第 4 页「近 7 天只有 2 条」不是缺陷

截图里总违规数显示 **2**，而第 2 页有 **11 条**。这是**正确的窗口口径**，不是数据丢失：

- `GET /api/stats` 默认 `days=7`，窗口 = `[今天-6 00:00:00, 今天 23:59:59.999999]`（契约 §6.8）；
- `demo_seed.py` 的 `frame_time` 落在 **10-01 ~ 10-05**，多数在 7 天窗口之外；
- 实测：`days=7` → 2 条，`days=30` → 11 条，`by_rule` = 4/4/3，**三分项之和 11 = total 11**。

**答辩讲法**：如果需要展示全量，把第 4 页时间范围切到「近 30 天」。
这正好可以演示窗口筛选本身，**不必为了好看去改数据**。
