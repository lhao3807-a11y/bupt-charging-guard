「桩」点北邮 · 充电桩车位防占系统

识别 → 判定 → 提醒 → 落库 闭环
演示流程图 · 答辩用

一、业务闭环

一次完整判定：从摄像头取帧到违规记录落库，全程自动，无需人工干预
1

车辆识别

摄像头取帧送入视觉模型：YOLOv8 检出车辆目标并给出置信度， HyperLPR 识别车牌字符，输出车牌号、车型（绿牌→新能源 / 蓝牌→燃油）与检测框。

POST /api/recognize
输入：帧引用 · 输出：RecognitionResult
→
2

违规判定

以车牌为键联结充电桩状态与系统阈值，依次命中四条规则； 命中即落库并生成违规记录，规则 ④（正常充电）不产生记录。

POST /api/judge
阈值一律读 system_config，禁止硬编码
→
3

主动提醒

按违规记录的车牌查绑定车主手机号，推送到短信沙箱（演示期不真实下发）， 回写提醒状态：未提醒 → 已提醒 / 失败。

POST /api/notify
手机号展示按 138****6621 脱敏
→
4

记录落库

违规记录写入 occupation_record，后台「违规记录查询」页可见； 同桩同规则且未提醒的记录复用为一条，避免轮询导致记录爆炸。

GET /api/records
支持车牌 / 车型 / 桩 ID / 规则 / 状态 / 时间筛选

二、系统分层

四层职责单一：上层只依赖下层的接口，判定语义全部收敛在判定层
展示层Vue 3 + Vite
后台 6 页 车辆信息管理 违规记录查询 充电状态展示 报警统计 系统参数配置 实时识别预览 Element Plus · ECharts
接口层FastAPI
POST /api/recognize POST /api/judge POST /api/notify GET /api/records GET /api/health GET /api/frame/latest（预留）
判定层rule_engine
四条规则 规则 ① 燃油车占位 规则 ② 异常占位 规则 ③ 充满未移车 规则 ④ 正常充电（不提醒）
数据层SQLAlchemy
vehicle charging_pile occupation_record system_config 开发期 SQLite → 目标 MySQL 8

三、四条判定规则

颜色顺序 = 严重度顺序，后台所有页面同序，不换色
rule_hit = 1
燃油车占位
蓝牌燃油车停在充电位上 —— 最严重，立即提醒驶离
rule_hit = 2
异常占位
新能源车停在充电位但未充电，且久停超过阈值（默认 30 分钟）
rule_hit = 3
充满未移车
充电已完成但超时未离场（默认 30 分钟），占用紧缺资源
rule_hit = 0
正常充电
合规使用，不产生违规记录、不发送提醒
