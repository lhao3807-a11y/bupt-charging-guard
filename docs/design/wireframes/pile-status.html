空态

桩数据来自种子与模拟器，空态最常见的原因是模拟器没启动，所以文案要指向排查动作。

暂无桩数据

charging_pile 表为空。请确认后端已建表并写入种子数据（启动时自动执行），或启动充电状态模拟器。

没有符合条件的桩

筛选状态不匹配。清空筛选条件即可看到全部桩位。

标注说明

本页对应开发大纲 M7「充电状态展示」，数据源 charging_pile（模拟）。

  1. 表格列 = charging_pile 全字段：桩 ID / 状态 / 绑定车牌 / 开始充电时间 / 充满时间，另加「操作」列。卡片视图展示同一批字段的另一种排布，两视图字段完全一致，用分段控件切换（对应 el-radio-button）。
  2. 「空闲 + 有绑定车牌」是真实业务场景：代表车已停在车位上但桩未在充电，正是规则 ②「异常占位」的判定输入。PILE-003 / PILE-006 即此状态，与第 2 页的记录 3 / 记录 6 对得上。
  3. 跨页数据自洽：本页 PILE-002（京AD12345 已充满，08:55 充满）↔ 第 2 页记录 5（同一车牌、同一桩、08:55:30 命中规则 ③）；PILE-005（京AD24680 已充满，12:10 充满）↔ 第 2 页记录 4。演示时两页互相对照，讲得通。
  4. 不用图表：本页只有 8 个桩、3 种状态，用统计卡 + 卡片网格比饼图更直观，图表集中在第 4 页（ECharts 选型见 component-inventory.md §3.1）。
  5. 免责说明不能省：红色是违规、橙色是待关注，而桩状态是模拟的。页面顶部必须写明「数据为模拟、预留 OCPP」，否则答辩时容易被追问「你的数据哪来的」。
  6. 空时间显示「—」并降级到 --text-tertiary：充电中/空闲的桩没有充满时间，留空白会被误判为渲染缺失。
  7. 桩 ID 与车牌用等宽（--font-family-mono），便于与第 2 页的「桩 ID」列逐位比对。
  8. 时间列补全日期：卡片视图因空间有限只显示时间（08:05:00），列表视图显示完整日期时间（2026-09-08 08:05:00）。同一页面内两种粒度并存时，卡片需带分组标题日期，避免歧义。
