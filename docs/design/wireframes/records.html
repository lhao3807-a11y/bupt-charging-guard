标注说明

本页是第 1 周 Demo 验收项（CONTRACT.md §11 第 5 项「后台违规记录查询页面能看到该条记录」），优先级高于其余 4 页。

  1. 表格列 = ViolationRecord 全字段：ID / 车牌 / 车型 / 桩 ID / 命中规则 / 命中时间 / 提醒状态 / 提醒时间，另加「操作」列。依据契约 §5 与 §1.1「表格列以对应表字段为准」，未新增字段、未自造枚举。
  2. ID 列必须展示、不可隐藏：契约 v1.2 起 POST /api/notify 的入参必须带 id（§6.3），id 是「定位要更新哪条记录」的唯一键。藏在 tooltip 里会让联调时无法核对。
  3. 表中不出现 rule_hit = 0：契约 §6.2 规定规则 ④（正常充电）判定返回 null，不落库，因此记录里只有 1 / 2 / 3。枚举 0 仅为兼容历史数据保留，所以「命中规则」筛选下拉只给 1 / 2 / 3 三项，不给「正常」。
  4. 不需要前端去重：契约 v1.2 §6.2 已定去重口径——同 pile_id + 同 rule_hit 且未提醒时，视为「同一违规持续中」，后端复用原记录并刷新 occur_time，不新增行。前端不要再自行合并同名记录，否则统计会与后端不一致。
  5. 操作列三态由 notify_status 决定：未提醒 → 「发送提醒」（主色文字按钮）；失败 → 「重试」（同 id 再调一次 notify）；已提醒 → 置灰文字不可点。这是纯前端行为差异，接口只需 id + notify_status，不改契约。
  6. 行内操作用文字按钮而非实心按钮：一屏十余行，实心按钮会把表格变成色块墙。依据 design-tokens.md §3.3 ⑤。
  7. 车型与命中规则必须语义自洽：rule_hit = 1（燃油占位）对应车型「燃油」；rule_hit = 2 / 3 对应车型「新能源」。线框数据已按此规则构造，前端无需校验，但演示数据不能配错，否则答辩现场一眼看穿。
  8. 提醒时间为空显示「—」并降级到 --text-tertiary，不留空白单元格，避免被误认为渲染失败。
  9. 数字与定长标识一律等宽：ID / 车牌 / 桩 ID / 时间用 --font-family-mono + tabular-nums，翻页时列宽不跳动。
  10. 空态两种文案：筛不出结果 → 「重置筛选」引导；库里确实没有 → 提示去录入车辆 / 触发识别。第二种同时是演示前自检：如果 Demo 时看到「暂无违规记录」，说明识别→判定链路没跑通。
