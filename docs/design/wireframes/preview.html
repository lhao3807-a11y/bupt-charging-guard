标注说明

  1. 导航第 6 项已解禁：CONTRACT v1.5 §1.1 起本页导航不再 disabled 置灰，「第 1 周预留」角标同步移除。tools/check_tokens.py 第 [5] 项已从「要求恰有 1 个 is-reserved」改为「要求 0 个」，6 页同改。
  2. 但接口仍未就绪：GET /api/frame/latest 按契约 §6.5 仍是预留端点。所以第 2 周本页是「可进入、有骨架、无真实数据」的占位页，不进第 2 周验收；完整实现为第 3 周。前端在接口就绪前打开本页，应显示上面的空态与说明条，不要报错、也不要伪造数据。
  3. 表格列严格取契约 §3.5 的 P6 登记：车牌 / 车型 / 桩 ID / 命中规则 / 命中时间，对应 occupation_record 的 plate / vtype / pile_id / rule_hit / occur_time。不新增业务字段；「操作」列本页不需要（发送提醒在第 2 页做）。
  4. 右侧「本次识别结果」不是表格列：confidence / frame_time 属 RecognitionResult（契约 §4）的接口字段，故不进 §3.5、也不算自造列。左侧「帧引用 / 轮询间隔 / 识别耗时」同理，是运行参数而非业务数据。
  5. 说明条是硬要求：el-alert（info）写明「仅展示最近一帧截图（轮询刷新），不接实时视频流」—— 开发大纲已确认此表述，答辩时避免被误解为真实视频流接入，不得删。
  6. 两种空态语义不同：①「取不到帧」是异常/未就绪，引导重试；②「未命中规则」是正常状态（规则 ④ 返回 null），不引导任何操作。混用会让演示时看不出系统到底是否正常。
  7. 规则色与其余 5 页同序：燃油车占位红 / 异常占位橙 / 充满未移车黄，与第 2 页表格、第 4 页图表完全一致（design-tokens.md §3.3①）。
