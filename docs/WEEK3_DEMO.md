## 1. 启动前自检（提前 10 分钟做完，别在现场调）

### 1.1 环境自检

```powershell
# ① 后端（**必须 cd backend**，从仓库根起会报 No module named 'app'）
cd backend
../.venv/Scripts/python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000

# ② 前端
cd frontend
npm run dev
```

> ⚠️ **Vite 在部分 Windows 环境监听 IPv6**，若 `127.0.0.1:5173` 连不上，改用 `localhost:5173`。

### 1.2 五个必查项（**任何一项不过就不要开始演示**）

| # | 检查 | 命令 / 方法 | 期望 | 不通过怎么办 |
|---|---|---|---|---|
| 1 | 后端存活 | 打开 `http://127.0.0.1:8000/api/records?page=1&size=1` | 200 且有 JSON | 检查是否从 `backend/` 启动 |
| 2 | 前端存活 | 打开 `http://localhost:5173/` | 登录页出现 | 重启 `npm run dev` |
| 3 | **代理贯通** | 在前端页内看第 2 页有无数据 | 表格有记录 | 检查后端是否在 8000 |
| 4 | **演示数据** | `python docs/design/tools/demo_seed.py` | 输出 `records 总数：11` | 见 §4 数据复原 |
| 5 | 权重/依赖 | 第 6 页能出图 | 显示样例静态帧 | 见 §4.3 显式 stub 回退 |

> **第 4 项是最容易翻车的一环** —— 种子脚本按「同桩 + 同规则 + 未提醒」复用记录，
> **重复跑会追加而不是覆盖**。所以务必先按 §4.1 清库，再跑种子。

## 3. 主线（第 2 页）怎么讲

### 3.1 帧 / 车牌 / 桩 的关联（**先建立这条链，后面都好讲**）

演示数据的关联（由 `demo_seed.py` 经契约端点产生，非手改数据库）：

| 车牌 | 车型 | 绑定桩 | 命中规则 | 颜色 |
|---|---|---|---|---|
| 京A88888 | 燃油 | PILE-004 | ① 燃油车占位 | 红 |
| 京AD24680 | 新能源 | PILE-003 | ② 异常占位 | 橙 |
| 京AD67890 | 新能源 | PILE-002 | ③ 充满未移车 | 黄 |
| 京AD12345 | 新能源 | PILE-001 | **④ 正常充电 → 不落库** | — |

**一句话讲法**：「同一条记录可以在第 2 页（事件）、第 3 页（桩）、第 4 页（统计）三页对上 ——
车牌、桩 ID、规则色序三处完全一致。」

### 3.2 提醒三态（**如实说，别吹**）

| 状态 | 画面 | 口径 |
|---|---|---|
| 已提醒（绿） | 记录 id=2 等 | 「沙箱写入成功。**演示环境，未真实下发短信**」 |
| 未提醒（黄） | 记录 id=6 / 9 等 | 「判定已命中，尚未执行发送」 |
| 失败（红） | 记录 id=3 / 7 等 | 「发送失败，**可人工重试**；重试只作用于同一条记录，不新增违规」 |

### 3.3 三个容易被问住的点（**提前准备答案**）

| 提问 | 怎么答 |
|---|---|
| 「短信真的发出去了吗？」 | **没有。** 沙箱只写库和日志，不调运营商接口。这是本周明确不做的范围（真实账号与模板审核未做）。 |
| 「充电桩状态是真的吗？」 | **不是。** 由后端种子与模拟器写入，是模拟状态；OCPP 适配层只留了接口边界。 |
| 「这个是视频吗？」 | **不是视频流。** 每 3 秒读一次最新静态截图，页面已注明。 |

## 4. 数据复原与应急

### 4.1 数据复原（**每次演示前必做**）

```powershell
# ① 停后端
# ② 删开发库（gitignore 的可再生产物，启动时自动重建 + 灌种子）
Remove-Item backend/app.db
# ③ 重启后端（见 §1.1），④ 重新灌演示数据
python docs/design/tools/demo_seed.py
```

> ⚠️ **只删 `backend/app.db`（开发库）。不要碰任何 MySQL 库。**
> 计划 §7：数据预置/清理不能指向开发以外或有价值的数据库。

### 4.2 空数据怎么办

若第 2 页表格为空：九成是后端没起或代理没通。先看后端窗口有没有报错，
再访问 `http://127.0.0.1:8000/api/records?page=1&size=1` 确认有 JSON。

### 4.3 显式 stub 回退（**只在 real 模式起不来时用，且必须说明**）

若实拍 real 链路（T3/T7）未能启动：

1. **在启动脚本里显式切 stub**，不要靠「自动降级」；
2. **在页面上口头说明**：「当前为 stub 模式，读取的是样例标注帧，不是实拍识别」；
3. 界面与日志都应可分辨（计划 L2 验收要求）。

> ⚠️ **不要静默切 stub**。静默降级等于把 stub 结果当成实拍结果讲，
> 一旦被追问「这是哪张图」就会露馅 —— 这正是计划反复强调「不能静默切换 stub」的原因。

### 6.1 正常场景怎么讲（**别拿「表格里没有这一行」当证据**）

正常充电按契约 §6.2 返回 `null`、**不落库**，所以第 2 页表格里本来就没有正常行。
若被问「正常场景你验证了吗」，**不要只说「表格里没有」** —— 那是弱证明。改用可复现的接口证据：

```bash
python docs/design/tools/demo_normal_scene.py --json
```

实测四条断言（凭据落盘 `docs/acceptance/week3/A04-normal-scene.json`）：

| 断言 | 实测 |
|---|---|
| 规则 ④ 返回 `null` | 响应体为 `null` |
| 违规记录总数不变 | 11 → 11 |
| 统计总数不变 | 11 → 11 |
| 「正常充电」分项计数不变 | 0 → 0 |

且脚本**全程不调用发送器**（`POST /api/notify`），对应 A04「不调用发送器」。

> 一句话讲法：「正常场景**不产生违规记录**，所以它正确地**不出现在表格里** ——
> 这不是漏数据，是设计。判定返回 `null`、记录数与统计数都不变，可用上面的脚本现场复现。」

### 6.2 失败后恢复怎么讲（**先声明驱动方式，别等人问**）

三张画面：`raw/w601-1-failed.png`（红「失败」+「重试提醒」）→
`w601-2-recovered.png`（绿「已提醒」+「发送提醒」）→ `w601-3-final.png`。

**主动说明边界**：「这三张是真实页面实拍，但**重试那一次请求是脚本发的** ——
前端点按钮走的是同一个 `POST /api/notify` 端点，所以画面与人工点击一致，
只是没人手按那个按钮。」

复现：`python docs/design/tools/demo_recovery_shots.py`（结束后自动还原演示数据）。
